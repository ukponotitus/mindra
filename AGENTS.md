# figma-make-app

React + Vite + Tailwind CSS project running inside Figma Make.

## Development Server

A Vite development server is **already running** on `$PORT` (default 8443). You don't need to start it manually.

- Preview URL: The user can access the running app through the preview panel
- Hot reload: Changes to source files are reflected immediately

## Project Structure

This is the canonical project structure. Start with task-relevant files below. Only follow imports or inspect other files when required, when a documented path is missing, or when the repository contradicts this guide.

- `src/main.tsx` - React entrypoint; imports `src/index.css` and mounts `src/App.tsx` into the `#root` element
- `src/App.tsx` - Primary application component and the usual starting point for UI work
- `src/index.css` - Global CSS entrypoint and Tailwind CSS v4 import
- `index.html` - Vite HTML shell containing the `#root` element and loading `src/main.tsx`
- `package.json` - Project dependencies and the Vite build, development, preview, and formatting scripts
- `vite.config.ts` - Vite configuration with React, Tailwind CSS v4, and Figma Make plugins plus the `@` alias for `src`
- `.mise.toml` - Toolchain versions for Node.js and pnpm

## Dependencies

- Runtime: React 19 and React DOM 19
- Styling: Tailwind CSS v4 with the `@tailwindcss/vite` plugin
- Build tooling: Vite 8, TypeScript 5.7, and `@vitejs/plugin-react`
- Formatting: oxfmt

## Styling

This project uses **Tailwind CSS v4** through the `@tailwindcss/vite` plugin configured in `vite.config.ts`. `src/index.css` imports Tailwind with `@import 'tailwindcss';`. Use Tailwind utility classes directly in JSX and put global CSS or Tailwind v4 theme customization in `src/index.css`. This scaffold does not need a Tailwind config file or PostCSS config.

`src/main.tsx` imports `src/index.css`, so global font wiring belongs in `src/index.css`. Keep CSS `@import` statements first, then add any `@font-face` rules and font-family defaults there.

Light and dark: every surface uses the theme tokens in `src/index.css` (`bg-card`, `bg-background`, `text-foreground`, `text-muted-foreground`, `border-border`, `bg-primary` with `text-primary-foreground`), never `bg-white` or grey shades, so dark mode only changes the tokens. `.dark` on `<html>` redefines them, turns the status colours' pale fills (red, emerald, amber 50 to 200) into tints of the card and their dark text shades (700 to 900) into light ones, and lightens `text-red-600`; a filled danger button hovers with `bg-red-600/90`, not `bg-red-700`. `src/lib/theme.ts` keeps the choice (Light, Dark or Device setting, `mindra.theme` on the device) and `useApplyTheme` in `DashboardShell` applies it inside the app only, so the landing and legal pages stay light. It's chosen in both account menus (`ThemeMenuItems`) and Settings → Appearance. The `dark:` variant is available for anything the tokens don't cover

## Code quality

- Use double quotes for strings containing apostrophes (`"We're here to help"`), or escape them in single-quoted strings. An unescaped apostrophe in a single-quoted string breaks the build.
- Ensure JSX tags are closed and braces are balanced.
- Export components as default exports.

The Billing page (`/billing`, in the account menu that opens upwards from the person's name at the bottom of the sidebar, with Settings and Log out) shows the workspace's plan from `GET /api/billing/`: where it comes from (Beta until the beta ends, then Free; or given by Mindra in the admin, with its end date), hours used this month and when they reset, connected accounts against the plan's limit, this month's AI-generated posts, clips (and the watermark), image or flyer projects, AI images and assistant messages against the plan's numbers (`posts_per_month`, `clips_per_month`, `picture_projects_per_month`, `ai_images_per_month`, `assistant_messages_per_month`, the last listed on the cards only once the assistant is on; the backend's `billing/usage.py` counts them as they're made), and the plans. Paying is through Paystack when the API has its key (`payments.available`); without it the page says to email for an upgrade. Owners and admins (`payments.can_manage`) choose a plan, monthly or yearly, on its card (`useCheckout`: `POST /api/billing/checkout/`, then Paystack's checkout page, which comes back to `/billing?reference=…`; the page checks it with `POST /api/billing/verify/` and shows the result, or a note for `?checkout=cancelled`). Switching from a paid plan asks first (the new plan starts once paid, the old one ends then, unrefunded). The current plan's card shows its renewal date, or that it's cancelled or its renewal failed, with Cancel plan, Keep (renew again), Change card (Paystack's page) and Pay now. Payments lists `payments.invoices`. An API error with `code: "plan_limit"` (`isPlanLimit` in `src/lib/api.ts`), or a saved message that ends "See the plans in Billing", gets a "See plans" link (`SeePlans`): in New Project, Processing, the project page, the clip editor, the "write posts" form, a content plan's post and Connected accounts. A clip made on the Free plan has `watermarked`; after an upgrade the clip editor offers to make it again without the mark

## Deploy

The live site is the static build (`dist/`) served by a Cloudflare Worker named `mindra` (static assets, plus a small script for short links only), connected to this repo so every push to `main` deploys, at https://mindra.online and https://www.mindra.online (custom domains on the Worker; the domain's DNS is on Cloudflare, registered at Namecheap). The API is at https://api.mindra.online (Render, a CNAME in Cloudflare set to DNS only). `wrangler.jsonc` holds its settings: the `dist/` folder, the `workers.dev` address (https://mindra.mindra-app.workers.dev) still switched on, and `not_found_handling: "single-page-application"` so every path that isn't a file gets `index.html` and React Router's deep links work.

- Short links: `worker/index.js` runs only for `/l/*` (`run_worker_first`); everything else is served as files without it. It passes `/l/<code>` to `API_URL` (in `wrangler.jsonc`'s `vars`, `https://api.mindra.online`) with the visitor's user agent and the country Cloudflare gives (`X-Mindra-Country`), and returns the API's redirect. Try it locally: build, then `npx wrangler dev --var API_URL:http://localhost:8000`.

- Build settings (Workers & Pages → mindra → Settings → Build): build command `pnpm run build`, deploy command `npx wrangler deploy`, root directory `/`.
- Environment variables (Production, and Preview if used): `VITE_API_URL`, the live API's URL with no trailing slash. Vite writes it into the build, so redeploy after changing it; a build without it calls `http://localhost:8000`. Optionally `PNPM_VERSION=10.34.3` to match `.mise.toml` (Cloudflare's default pnpm also installs this lockfile). Leave `FIGMA_PUBLIC_URL` unset so the base is `/`.
- Node: `.node-version` pins 22.23.3, which Cloudflare's build reads. React Router 8 needs Node 22.22 or newer, and Cloudflare's default (22.16) is older.
- Install: the build installs from `pnpm-lock.yaml`. Commit that lockfile and not `package-lock.json`, and update it (`pnpm install`) whenever `package.json` changes.
- Deep links (`/projects/<id>`, `/privacy`) come from `not_found_handling` in `wrangler.jsonc`. Keep its `compatibility_date` no newer than the local wrangler supports, or `wrangler dev` won't start.
- The API must accept the site's origin: set `CORS_ALLOWED_ORIGINS` and `FRONTEND_URL` on the backend (see `../mindra-backend/README.md`).
- Search engines: `.figma/make/site.json` has `"robots": { "index": false }`, so the build adds `noindex` and a `robots.txt` that blocks crawlers. Change it when the landing page should appear in search. The page title, description and sharing image (`public/og-image.png`, 1200x630) are in `site.json`; `index.html` has the canonical address, `og:url` and the SoftwareApplication structured data, and the prerender gives each legal page its own canonical address.
- Sign-up asks for an invite code when the API says so (`GET /api/auth/signup-options/`, on when the backend's `BETA_INVITE_CODES` is set).
- Privacy in the app (the backend's README, "Privacy"): sign-up has an "I'm 18 or older, and I agree to the Terms and Privacy Policy" checkbox (`confirms_age`); Settings → Account → Your data (`src/components/settings/YourData.tsx`) downloads a copy (`/api/auth/export/`) and deletes the account after the password (`/api/auth/delete-account/`), then reloads to `/login?account=deleted`, which says so; disconnecting an account says its numbers are deleted from Analytics; the Data Deletion page shows what became of a Meta request by its code. Journey test: `your-data.spec.ts`
- Legal pages: `/privacy`, `/terms` and `/data-deletion` (`src/pages/Privacy.tsx`, `Terms.tsx`, `DataDeletion.tsx`, laid out by `src/components/landing/LegalLayout.tsx`, which styles plain h2, h3, p, lists and tables; rewritten 1 November 2026 from the privacy audit: lawful bases, every provider and country, transfers, retention, rights and the NDPC, breaches within 72 hours, YouTube's required terms and revocation link, provider-by-provider deletion. Keep them true to the code: who writes posts (Gemini, free tier for now), the assistant (Claude), what disconnecting deletes), linked from the landing footer and the sign-up form. `pnpm run build` runs `vite build && node scripts/prerender.mjs`, which renders those three pages to `dist/privacy.html`, `terms.html` and `data-deletion.html` with their full text (so Meta's checker and other crawlers without JavaScript can read them) and allows them in `robots.txt`, with `/l/` (Mindra's short links, so X's and LinkedIn's link previews can follow them); the app takes over in the browser. `/data-deletion?code=…` is where Meta's data deletion callback sends people. The company name, contact email and governing country are in `src/lib/legal.ts`; change `LEGAL_LAST_UPDATED` whenever any of the three pages changes. `public/icons/app-icon-1024.png` is the icon for the Meta app dashboard.
- Try a production build locally: `VITE_API_URL=http://localhost:8000 pnpm build`, then `pnpm preview --port 4173` (without `--port` it tries the dev server's port).

## Marketing video

`campaign/` is a separate Remotion project (its own `package.json`, not part of the Vite build) for the 60-second Facebook Reels launch video (1080x1920, 30 fps).
